# SplitEase — CPAD Laboratory Project

## Project
SplitEase is a cross-platform expense-sharing application inspired by the
concept of applications such as Splitwise.

## Academic Context
This is a Cross Platform App Development (CPAD) laboratory project.
The same application will be progressively developed throughout the semester
across multiple laboratory experiments.

## Current Experiment
Experiment No. 1:
"Develop application using Flutter widgets"

## Current Objective
For Experiment 1, create a polished static UI demonstrating commonly used
Flutter widgets.

This experiment should NOT implement:
- Authentication
- Database
- Firebase
- REST APIs
- Backend
- Expense calculation
- Real-time functionality
- Notifications
- AI functionality
- Complex state management

Use static/dummy data.

## Application Identity

Application name:
SplitEase

Purpose:
Help users track shared expenses between friends, roommates, classmates,
and groups.

## Experiment 1 UI

Create a mobile expense-sharing dashboard containing:

1. App bar
   - SplitEase title
   - User/profile icon

2. Greeting
   - "Good afternoon, Sneha!"
   - Short supporting text

3. Balance summary card
   - Total balance
   - You owe
   - You are owed

4. Groups section
   - Goa Trip
   - College Friends
   - Roommates
   - Each represented using a Card

5. Recent activity section
   - Static expense/activity entries

6. Add Expense button
   - UI only
   - No actual expense functionality

7. Bottom navigation
   - Home
   - Groups
   - Activity
   - Profile
   - Navigation may remain static for Experiment 1

## Design

Create a clean, modern, student-friendly expense-sharing application.

Use a consistent color palette and Material Design principles.

The UI should look like a real mobile application but remain simple enough
for a beginner CPAD laboratory experiment.

Avoid excessive animations and unnecessary dependencies.

## Code quality

- Keep the code understandable for a college student.
- Use meaningful variable and widget names.
- Use reusable widgets for repeated UI components.
- Do not over-engineer.
- Do not introduce unnecessary packages.
- Keep the application runnable.
- Follow standard Flutter/Dart conventions.

## Important academic rule

Only implement functionality required for Experiment 1.
Do not prematurely implement features belonging to later experiments.

The code should be easy to explain in a CPAD laboratory viva.
